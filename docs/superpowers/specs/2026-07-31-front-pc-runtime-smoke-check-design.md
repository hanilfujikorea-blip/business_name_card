# 앞자리 PC 운영 모듈 점검 전환 설계

## 배경

오프라인 설치 배치파일은 필수 패키지를 설치한 뒤 저장소의 전체 개발 테스트를 실행한다. 앞자리 PC에는 운영에 필요하지 않은 `python-docx`와 Git이 없으므로, 개발지침서 테스트와 Git 속성 테스트가 실패해 설치 전체가 실패한 것처럼 표시된다.

## 목표

- 앞자리 PC 설치 성공 여부를 실제 운영에 필요한 구성요소만으로 판단한다.
- Git과 `python-docx`를 앞자리 PC에 추가 설치하지 않는다.
- 설치 검증 과정에서 메일을 조회·발송하거나 포털을 시작하지 않는다.
- 검증 실패 시 Python 종료 코드를 보존한다.

## 설계

`offline_setup/install_offline.bat`의 전체 `unittest discover` 실행을 운영 모듈 스모크 점검으로 교체한다. 스모크 점검은 설치된 Python으로 다음 모듈을 불러온다.

- `openpyxl`
- `dotenv`
- `business_card_mailer`
- `business_card_portal`

프로젝트 폴더에서 import만 수행하므로 서버를 열거나 메일 API를 호출하지 않는다. 성공하면 설치 완료 문구를 출력하고, 실패하면 `RUNTIME_SMOKE_CHECK_FAILED`와 원래 종료 코드를 출력한다.

## 테스트

- 가짜 Python 실행기를 사용한 CMD 블랙박스 테스트에서 개발 테스트 명령을 만나면 실패하도록 한다.
- 운영 스모크 점검 명령을 만나면 성공하도록 하여 설치 배치파일이 Git이나 `python-docx` 없이 완료되는지 검증한다.
- 기존 해시·변조·한글 및 공백 경로·오류 코드 보존 테스트를 유지한다.
- 전체 개발 테스트는 개발 PC의 일반 테스트 명령에서 계속 실행한다.

## 안내서 변경

`앞자리PC_설치_실행.txt`의 “전체 프로젝트 테스트” 표현을 “운영 필수 모듈 동작 확인”으로 바꾼다. 앞자리 PC에 Git 또는 `python-docx`를 설치하라는 지시는 추가하지 않는다.

## 제외 범위

- 오프라인 휠 목록 변경
- Git 설치
- `python-docx` 설치
- 메일 설정, 수신·참조 주소, 발송 모드 변경
- 포털 자동 시작 또는 실제 메일 발송
