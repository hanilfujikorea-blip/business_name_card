# 앞자리 PC 완전 오프라인 설치 묶음 설계

## 목적

앞자리 PC가 HTTPS 인증서 오류 `0x80072f0d`로 Python 및 PyPI 패키지를 내려받지 못해도 K Group 명함 자동발주 시스템을 설치하고 검증할 수 있게 한다.

## 구성

프로젝트 루트에 `offline_setup` 폴더를 추가한다.

- `offline_setup/python-3.13.14-amd64.exe`: Python.org 공식 Windows 64비트 오프라인 설치 파일
- `offline_setup/wheels/`: `requirements.txt`와 모든 하위 의존성의 로컬 배포 파일
- `offline_setup/install_offline.bat`: Python 설치, 로컬 패키지 설치, 프로젝트 테스트를 순서대로 실행하는 배치파일
- `offline_setup/SHA256SUMS.txt`: 설치 파일과 로컬 패키지의 SHA-256 목록

기존 `앞자리PC_설치_실행.txt`는 온라인 `winget` 및 온라인 `pip install` 절차를 제거하고 오프라인 배치파일 실행 절차로 바꾼다.

## 경로 처리

- 설치 배치파일은 `%~dp0`를 기준으로 프로젝트 루트를 계산한다.
- 프로젝트가 `C:\WA\2026.07 명함 자동발주 시스템` 또는 다른 위치에 있어도 같은 파일을 사용한다.
- 운영포털 실행 배치파일은 기존처럼 자신의 위치를 기준으로 동작한다.
- 작업 스케줄러 등록 명령은 현재 프로젝트의 절대 경로를 실행 시점에 계산해 고정된 개발 PC 경로를 사용하지 않는다.

## 설치 흐름

1. 배치파일이 공식 Python 설치 파일의 SHA-256을 검사한다.
2. Python 3.13이 없으면 사용자 범위로 자동 설치한다.
3. 설치된 Python 실행 파일을 다시 탐색한다.
4. `pip`가 인터넷을 조회하지 않도록 `--no-index --find-links`로 로컬 패키지만 설치한다.
5. `py -B -m unittest discover -s tests -v`에 해당하는 전체 프로젝트 테스트를 실행한다.
6. 어느 단계든 실패하면 명확한 오류 메시지와 종료 코드를 반환하고 포털은 시작하지 않는다.

## 보안 및 무결성

- Python 설치 파일은 Python.org 공식 3.13.14 Windows 64비트 파일만 사용한다.
- 공식 SHA-256은 `c54d9b9bbb8a36e6489363ddd01139707fd781d72f1f9e90c7ec65d0061368e0`이다.
- 모든 오프라인 자산의 SHA-256을 기록하고 생성 직후 다시 검증한다.
- 인증서 검사 비활성화, `--trusted-host`, HTTP 다운로드는 사용하지 않는다.
- `.env`, 메일 주소, 토큰, 운영 상태 파일은 변경하거나 묶음에 새로 기록하지 않는다.

## 검증 기준

- 공식 Python 설치 파일의 SHA-256이 기대값과 일치한다.
- `wheels` 폴더만으로 `requirements.txt`의 모든 의존성을 해석할 수 있다.
- 임시 격리 환경에서 인터넷 접근 없이 패키지 설치가 성공한다.
- 설치 배치파일이 경로에 공백과 한글이 있어도 프로젝트 루트를 올바르게 계산한다.
- 기존 전체 테스트 111개가 통과한다.
- TXT에 `winget install`, 온라인 `pip install`, 개발 PC 고정 경로가 남아 있지 않는다.
